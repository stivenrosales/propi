# Spanish and English (i18n)

Objective: Propi speaks Spanish and English everywhere people read it (landing, legal pages, web app, admin, Slack messages, emails), picks the language automatically, and lets each workspace and each person change it.
Branch: feat/i18n (from feat/launch-polish). Delivery: ask-on-risk. Test runner: vitest on Postgres (`DATABASE_URL=postgresql://propi:propi@localhost:55433/propi pnpm test`), `pnpm typecheck`, `pnpm --filter @propi/web build` (typecheck does not cover apps/web), Playwright screenshots.

## Specs

- **S1 (user, verbatim, 2026-11-26):** "Todo esta en ingles, tambien hagamos que sea español amigo, que dependendo de launbacion y setearlo asi por default, igual la landing, ademas aque se pueda configura de la mejor manera".
- **S2 locales (assumption, decided by the parent):** `en` and `es`. Spanish is neutral Latin American Spanish with tú (no voseo, no regional slang), matching the product's warm voice. Every user-facing string has both versions; a missing key fails a test, never renders a raw key. Currency names set by admins (taco/tacos) are workspace data and are not translated.
- **S3 automatic default (assumption):** "dependiendo de la ubicación" is implemented with what the request carries, not IP geolocation (DNS is not proxied, so no geo header exists): landing and signed-out pages pick `es` when the browser's Accept-Language prefers any Spanish variant, else `en`. Inside the app and in Slack the order is: the member's own choice → the member's Slack locale (users.info `locale`, es-* → es) → the workspace default language → `en`. A new workspace's default language comes from the installer's Slack locale at install time.
- **S4 configurable "de la mejor manera" (assumption):** (a) a language switcher (ES | EN) in the landing header/footer and on the sign-in page, remembered in a cookie; (b) admins set the workspace default language in Settings; (c) each member sets their own language in Profile ("Automatic" = follow Slack locale/workspace default, or a fixed language); (d) the choice applies to web pages, Slack DMs/App Home/modals/ephemeral messages and emails sent to that member; channel posts use the workspace default. `<html lang>` and page metadata follow the language. Dates and numbers use the language's formatting.
- **S5 SEO for the landing (assumption):** the landing and legal pages render the chosen language on the same URLs (no /es prefix) with `hreflang`-free behaviour; metadata title/description translated.
