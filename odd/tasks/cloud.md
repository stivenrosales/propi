# Propi cloud (multi-tenant) with Polar billing

Objective: any Slack workspace installs the hosted Propi from propihq.com, runs isolated from every other workspace, and pays through Polar. Pearson keeps working without reinstalling.
Branch: feat/cloud (based on feat/ui-polish). Delivery: ask-on-risk. Test runner: vitest on Postgres (`pnpm test`), `pnpm typecheck`, Playwright for UI.

## Specs

- **S1 (user, verbatim):** "hagamos la version nube". Design shape A chosen by the user: one bot token per workspace, encrypted in `installation`, `SlackGateway.forWorkspace(ws)` as the only way to get a Slack client, `workspaces()` = active installations.
- **S2 Slack install (OAuth v2):** propihq.com has an "Add to Slack" entry that starts `oauth.v2.access` with a signed `state`. The callback stores the bot token encrypted in `installation.data_enc` (AES-GCM, `ENCRYPTION_KEY`), creates the workspace on first install and makes the installing user (`authed_user.id`) the first admin (spec S5). A reinstall refreshes the token and clears `uninstalled_at`; roles never change on reinstall. The workspace timezone comes from the installer's Slack profile (`tz`), falling back to `PROPI_TIMEZONE`.
- **S3 runtime per workspace:** the server serves every active installation at once. Events, slash commands, actions, App Home, the outbox relay, scheduler ticks, webhook delivery and the profile sweep each use the token of the workspace they belong to. No code path sends with another workspace's token. Lookup caches are keyed by team. `app_uninstalled` / `tokens_revoked` mark only that installation uninstalled (S72: data kept) and stop its sends.
- **S4 Pearson migration:** Pearson keeps working with no reinstall. On start, when `SLACK_BOT_TOKEN` is set and the installation of its team has no stored token, the server stores that token in the installation (one-time adopt). After that `SLACK_BOT_TOKEN` and `SLACK_INSTALLER_USER_ID` are optional and documented as legacy self-host bootstrap.
- **S5 web sign-in across workspaces:** Slack sign-in resolves the workspace from the signed-in team, as today. A team without an installation sees "Propi isn't installed in this Slack workspace yet" with the Add to Slack button.
- **S6 Polar billing (user, verbatim):** "los pago seran via polar.sh". Plans (assumption, editable in Polar): **Free** up to 10 active members; **Pro** priced per member per month through Polar. Admins upgrade from admin settings via a Polar checkout tied to the workspace (`metadata.workspaceId`), and manage or cancel through the Polar customer portal. Polar webhooks (signature verified, standard-webhooks) keep a per-workspace subscription record; processing is idempotent by event id.
- **S7 entitlement (assumption):** recognition never stops and no data is lost. A Free workspace over 10 active members keeps gifting, but the reward shop does not accept new redemptions and admins see an upgrade prompt in the web and App Home. Pro (active, or canceled until period end) lifts the limit. Pearson is `comped` (treated as Pro, never billed).
- **S8 setup (authorized by the user, L3-L4):** Polar org Propi in sandbox and live with products; API token and webhook secret in env, never committed; Slack app Propi (A0CLVJBJX54) publicly distributed with the install redirect URL; a second test workspace installs the app.
- **S9 done (stop condition):** a second Slack workspace installs from propihq.com, gives and receives recognition isolated from Pearson (no cross-workspace reads or sends), and an admin pays Pro; tests and typecheck green; deployed to haiku-vps; Pearson keeps working.

- **S10 legal pages (launch):** propihq.com serves `/privacy` and `/terms` (currently 404), linked from the site footer and the sign-in page. Facts to state: operator Stiven Rosales (individual, Peru), contact hola@propihq.com; Polar is merchant of record for payments; data stored: Slack profile (id, name, email, avatar, timezone), recognition data (gifts, ledger, redemptions), workspace settings; subprocessors: Slack, Polar (+Stripe), Resend (email), PostHog (analytics), OVH VPS (hosting), Cloudflare (DNS). Export as CSV any time; uninstall keeps data until an explicit deletion request (S72). Assumption: plain-language template, not legal advice.
- **S11 seats follow active members (launch):** a Pro subscription's seats in Polar track the workspace's active members (verifier advisory "seats fixed at checkout"). When the active count differs from the subscription's seats, Propi updates the Polar subscription seats (proration per Polar default). Runs from the server periodically and is idempotent; never for comped or Free workspaces.
- **S12 billing hardening (verifier advisories):** (a) a second checkout or a foreign subscription event never overwrites an active subscription of a different subscription id for the same workspace unless the stored one is no longer active; the Upgrade button is hidden while a subscription is active; (b) `Contribute` to a group reward obeys the same plan limit as redemptions (`plan_limit`).
